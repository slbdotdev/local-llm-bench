## The three most surprising things

**1. Every fairness defect that mattered was found by a second model doing the task, not by a
checker.** Four defects survived the reference, sandbox, and perturbation checks:

| slot | defect | the instrument that found it |
| --- | --- | --- |
| m01-main-claude | `active_count()` underspecified; the material stated half the rule | Haiku disagreeing with my reference and being right |
| m04-main-claude | the test invocation was never stated; the grader supplied it silently | both arms restructuring the tree to make the tests runnable — one added a `.venv`, one moved the package to the root |
| m02-main-luna | the grader required backticks around a table key the prompt never asked for | Sonnet and Haiku writing the same correct answer in two house styles |
| m05-cheap-glm | a subcheck scored a *classification* the material could not settle | two Claude arms giving one non-reference attribution, then Luna giving a third |

Rule: **a task is not finished when its grader is clean; it is finished when a reader who is not
its author has done it.**

**2. A grader ate the answer it was grading:** `m10-main-claude` went from 9/9 `correct` to 8/9
`confidently_wrong` on a second grading because it restored the manifest but not the regenerated CSV.
`probe_idempotence.py` now grades twice; graders must restore every file they disturb.

**3. Two of three families independently wrote prompts that gave away the answer:** GLM found
`m10-main-claude`, `m02-main-luna`, and `m01-cheap-luna` answerable from prompt-visible facts.
This has no checker, probe, or reference-arm signal; it justifies the roundtable.

## What is unfinished

1. **Calibration.** Nothing here evaluates a quant. No GPU was touched, no Ollama daemon was
   touched, no local model was run. Section "The calibration plan for tomorrow" below is the
   whole of what remains, and its step 1 (confirm the rung against v6's handoff) is still open
   because v6's handoff was a skeleton when this campaign started.
2. **The ZCode arm — not run by the owner's instruction, and the only missing row.**
   `authoring/run_zcode_arm.py` is serial, stages Windows-visible sandboxes, gates launches at 85% via `plan-usage.py`, records failed `1302` as `rate_limited`, and reads `final.txt`.
   `glm` and `zcode` would isolate harness effects; pi rescued twenty of twenty saturated-window runs, where ZCode has no equivalent.
3. **Sandboxes must move out of the repository before anything is scored.** `sanity.py` now takes
   `V7_SANDBOX_ROOT`; the calibration run must set it to a path outside every git checkout. A
   sandbox under the bench's own tree is one `git show HEAD:<path>` away from the hidden grader,
   and a Sonnet trial reached for `git status` and `git show HEAD:...` unprompted last night and
   said so. Nothing leaked and no result is in doubt, but "we asked it not to" is not a control.
   **The default is still the old location** so last night's evidence stays readable; changing it
   is one environment variable and it is the first thing to do tomorrow.
4. **Three known soft spots are on the hardening list rather than repaired.** `m06-main-glm`
   carries main-band material and cheap-band traversal — mode 6 is intrinsically short-traversal,
   since a failing check names its own file in the traceback. `m09-main-glm`'s governing-lift
   proviso is never exercised by its data, so a pedantic reader lands right without applying it.
   And `m05-cheap-glm` lost a subcheck (6 -> 5) rather than gaining a rewritten rate card; the
   better task states in R5 that the fuel base excludes the supplements, which makes the
   attribution decidable and the content subcheck restorable, and that is a calibration-day edit
   with time to re-verify four pricing scenarios. All three are in `roundtable.md` with the
   reasoning; none is a fairness defect.
5. **Repeat trials.** Every arm row is a single trial per task. The plan's step 6 wants three
   trials per task on whatever moves during calibration.
6. **The Z.ai five-hour window is spent and resets at `2026-09-05T08:50:42Z`.** It was 4% at start (D7-6) and **98-99%** at end; weekly usage was 19%.
   Read it with `python3 ~/ansible-slb/scripts/plan-usage.py`, which never prints the key.
   **Launch no GLM work before reset**: `1302` retries make saturation look slow; the GLM arm cost 1,344 s for 305 s of work.
