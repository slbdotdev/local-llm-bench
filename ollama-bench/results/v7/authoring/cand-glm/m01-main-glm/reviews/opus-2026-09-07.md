## 6. Findings

None changes the reference answer, the grader, or the mode measured. Ordered by how much they
matter to the record.

**F1 — `NOTES.md:52` states something the material contradicts.** "No single grep assembles it
either. `dwell` never appears in a stage's own document or module" is false: `grep -ril dwell
seed/` hits all 20 stage documents and all 20 modules. `docs/<stage>.md:17` contains the literal
lowercase word ("the seconds this stage currently honours as its dwell") and the key `dwell_s`;
every module carries `EFFECTIVE_DWELL_S` at line 14. The single grep the note says does not exist
is exactly the two-grep bypass I ran. The *conclusion* survives — I verified that grep yields
`confidently_wrong` — and §2 ¶2 of the same file argues the real, structural defence correctly.
So this sentence is both false and unnecessary, and it should be struck rather than repaired.

**F2 — `NOTES.md:48` overstates the required traversal by about 3×.** "The traversal a correct
answer requires is **23134 of 32213 material tokens (71.8%)**". The arithmetic is right for the
set described — I reproduced 23,134 exactly as every stage document plus every stage module plus
the branch records plus `config/manifest.json`, less `docs/architecture.md`, `docs/operations.md`
and `src/cordage/__init__.py` — but that set is a *thorough* solve, not a *required* one. A
solver that reads `history/branches/README.md` early learns that only 11 stages have any branch
record and that the rest still equal their constant, and `RN-0212` then cuts those 11 to 6. The
strictly necessary set is `README.md`, `config/manifest.json`, `history/branches/README.md`,
`RN-0212`, the decision note, the 16 branch records, 6 stage documents and 4 modules =
**8,221 tokens, 25.5%**. Since plan-r3 2.1's amendment makes coverage a diagnostic reported
beside every row, 71.8% would be read as an expected-coverage figure and it is not one. Related
and worth the manager's attention: the natural solve path here is *recursive* grep over `docs/`
and `src/`, whose command string names directories rather than files, so under plan-r3 2.5's
token-scan attribution this task is likely to *measure* lower coverage than it earns. That is a
property of the instrument, not of the candidate.

**F3 — dangling top-authority pointer in the seed.** `seed/README.md:11` ("`docs/policy/` — the
rules that outrank both of the above"), `seed/README.md:47` ("a policy under `docs/policy/`
outranks everything else") and `seed/docs/operations.md:45` ("Retention is governed by
`docs/policy/`") all name a directory that does not exist. A solver told the highest authority
lives there can spend turns looking, and could reasonably conclude the material is incomplete.
It is not answer-changing — no such policy exists to conflict with `RN-0212` — and one `ls`
settles it, so I do not treat it as a fairness failure. Note that the neighbouring clause,
"Documentation under `docs/` outranks a history entry", is a sharper trap than the missing
directory: read alone it implies `docs/replay.md` outranks the branch history and nothing can
ever be stale. What resolves it is that `RN-0212`, itself under `docs/`, explicitly delegates the
computation to the decision note under `history/branches/`. That chain is sound but subtle, and
it is the single most likely place for a *correct-but-unlucky* model to go wrong.

**F4 — `selfcheck.py:30-32` mislabels a case.** The case named "stops at the first branch record,
never sees a revert" is graded with an empty stale set and `net_dwell_change: 0`. A solver that
actually stops at the first record reports `checkpoint, envelope` / `0`, because
`checkpoint-01.md` and `envelope-01.md` both say in their own rationale that the document was
never brought in line. I graded that answer: 5/7, `confidently_wrong`, so grading is unaffected
and `selfcheck.py` still passes — only the label misdescribes the wrong course it stands for.

**F5 — cosmetic generator noise in the seed.** `settled` is duplicated in three stages, in both
the module tuple and the document's States list: `src/cordage/audit_flow.py`,
`replay_gate.py:15`, `rollup_view.py`, and `docs/audit.md`, `docs/replay.md`, `docs/rollup.md`.
`replay_gate.py:50` sets `record["state"] = "narrowd"`. All 20 documents say "Both are read from
the `<stage>` section" above a three-row table. None is load-bearing, and the duplication is at
least *consistent* between document and module, so it cannot mislead on the answer. It is visible
sloppiness in material a careful model reads, and mode 1 is not a defect-hunting mode.

**F6 — minor grader strictness on one free-text field.** `authority` uses kind `exact`
(`test.py:97`), so `RN-0212-dwell-onboarding` (the filename stem) scores 6/7,
`confidently_wrong`, as would `rn-0212`. The prompt asks for "the identifier", and the note's own
heading separates `RN-0212` from its title, so I judge this acceptable; if the seat wants slack,
`'authority': 'ci'` in `kinds` is the one-line change. Noted in the other direction for symmetry:
`_norm_list` splits on commas *and* whitespace (`test.py:267-270`), so a space-separated stage
list passes 7/7 even though the prompt says "separated by commas" — leniency on a stated point,
but it errs toward accepting a correct answer, which is the safe direction.
