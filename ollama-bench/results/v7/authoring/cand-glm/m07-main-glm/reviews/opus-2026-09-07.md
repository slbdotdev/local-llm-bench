## 3. Finding 1 - rung 0 fails: `bound_module` is answerable by one grep (blocking)

NOTES section 2 rests the whole rung-0 case on `bound_module`, and says so:

> The report also states `bound_module` ... so the qualification puzzle is a scored fact and
> not decoration a solver can skip past on the way to the five obvious sites.

That concession is correct, and it is load-bearing, because the other three fields need no
traversal:

- `symbol_new` is in the prompt;
- `symbol_old` is handed over by `src/ember/ext/handle_bridge.py:20-22`, a 22-line file that
  `README.md:49-55` points at by name. The "first verb method of the qualifying stage" rule is
  a redundant second derivation of a fact sitting in plain sight in a file the solver must
  edit anyway;
- `sites` is `grep -rl coalesce` (15 files) filtered by the prompt's own enumeration, which
  names both the inclusion set ("bridge module, lookup table, serializer, documentation
  example, regression test" + one config string) and the exclusion set ("the bound stage's own
  module", "other, unrelated stages' own modules", "a withdrawn decision record"). The six
  fall out with no arithmetic.

So `bound_module` is the only field the 79.6% traversal protects - and it leaks:

    seed/docs/architecture.md:12      2. `replay` (recovery)
    seed/docs/replay.md:7             The replay stage is the recovery boundary of the ember-course pipeline.
    seed/src/ember/replay_view.py:1   """replay_view: recovery handling for the ember-course pipeline.

`docs/architecture.md:11-29` is a **one-file index that tags all nineteen stages with a role
word**, and `replay` is the unique `(recovery)` entry. The subsystem describes itself, in three
places the solver reads first, as bridging a stage's **recovery** operation -
`prompt.md` ("one pipeline stage's own recovery operation"), `README.md:51` (same words),
`handle_bridge.py:1` (same words). `grep -rn recovery seed/docs/architecture.md` therefore
returns the bound stage directly. `replay_view.py:1` is the only module docstring reading
"recovery handling"; the other eighteen read "limits", "evidence", "fanout", "shutdown", etc.

This is exactly the index-leak class NOTES section 2 claims to have closed:

> never into `config/manifest.json`, `docs/operations.md`, a history entry or a test, all of
> which echo `limit`/`window_s` for every stage in one small file and would have let this rule
> be answered from two files instead of the whole tree ... checked mechanically by
> `r2/check_index_leak.py`.

The check evidently looked for a numeric `RECOVERY_BUDGET` index and did not consider that
`docs/architecture.md` is an index of *stage role words*, and that the subsystem's own
self-description supplies the role word for exactly one stage. NOTES section 2 notices the
`recovery` overlap but reads it only as an anti-glob property - "every token any one of them
carries (`handle`, `recovery`, `op`, `support`) is also carried by at least one file that must
NOT be touched, chiefly `replay` itself" - and misses that the same overlap is a *positive*
pointer to the one scored fact the traversal exists to defend.

Reference answer reachable from: `prompt.md`, `README.md` (625 tok), `handle_bridge.py`
(258 tok), `docs/architecture.md` (354 tok), plus one `grep -rl coalesce` whose output is
filenames, not content. **1,237 of 29,624 material tokens, 4.2%**, against the declared
23,572 / 79.6%. The declared figure is what a maximally diligent solver reads, not a lower
bound on what a passing one must. The grader scores the shortcut solver and the traversing
solver identically at 9/9 `correct` and cannot tell them apart - the D7-37 / D7-38 condition
plan-r3 section 3.5 puts ahead of the other three rungs.

**Fix (either, preferably both).** (a) Make the shortcut *wrong* rather than merely
unnecessary: move the `(recovery)` role tag in `docs/architecture.md:12` onto a stage the rule
excludes - `audit` (superseded, +28) is the natural decoy - and reword `docs/replay.md:7`
("recovery boundary") and `replay_view.py:1` ("recovery handling") so that no material
statement identifies the bound stage by the subsystem's own noun. Grepping `recovery` then
lands on a stage `history/0002` disqualifies. (b) Add a fifth scored key that only the
arithmetic yields, e.g. `declared_budget: 135` and `real_budget: 165`, so the traversal is
graded rather than merely available. (b) alone is the smaller edit and does not disturb the
corpus; (a) alone leaves a 1-in-2 guess between `replay_view` and `drain_core`, the two stages
whose first verb method is `coalesce`.

## 4. Finding 2 - every stated module path in the material contradicts the tree (fairness)

`bound_module` is graded exact-match (`kind` defaults to `exact`) against
`src/ember/replay_view.py`. **Every statement of a module path in the seed omits the `ember/`
package segment:**

    seed/README.md:23-41    | replay | `src/replay_view.py` | ... |   (all 19 rows wrong)
    seed/docs/replay.md:3   *Owner: E. Thorsdottir (Data Stewardship). Module: `src/replay_view.py`.*
                             (line 3 of all 19 stage docs, all wrong)

Verified: all 19 README table paths and all 19 `docs/<stage>.md:3` paths point at
`src/<module>.py`; none of those files exists. The only place in the entire corpus that spells
a correct path is `README.md:53`, incidentally, for the `src/ember/ext/` directory. Nothing
corrects the table.

A solver that answers `bound_module` from the material as written - which is what the task
asks it to do - writes `src/replay_view.py` and is graded `confidently_wrong`. Confirmed by
probe: a workspace with all six sites byte-perfect and only the path form differing scores
8/9. The mitigation is indirect and accidental: `sites` forces the solver to write
`src/ember/ext/...`, so internal consistency nudges it toward the right form for
`bound_module`. That is luck, not design, and it cuts against Finding 1 - the shortcut solver
that greps `architecture.md` may well pass while a solver that faithfully reads the stage
documentation fails.

**Fix.** Rewrite the 19 README table rows and the 19 `docs/<stage>.md:3` lines to
`src/ember/<module>.py`. This is a generator-level fix and touches every stage doc, so it
should be made together with Finding 1's, in the one revision.

## 7. What remains uncertain

- **Whether the review's own scope is right about `docs/architecture.md`.** The role tags are
  plausibly deliberate flavour rather than an oversight; if the author intends the bound stage
  to be identifiable that way, then rung 0 was never met on this design and the fix is
  Finding 1(b), not a corpus edit. Either way the current state fails the gate.
- **Where the grader file sits at run time.** `_hidden_test.py` is whitelisted by the scope
  gate but `test.py` is not, so a harness that copies the grader in under its own name will
  trip `out-of-scope file(s) created`. This is shared round-2 harness body, so it is almost
  certainly a convention I cannot see rather than a defect; probes here used the whitelisted
  name. Not counted as a finding.
- **`r2/check_index_leak.py` was not read** (outside the directory this review is scoped to),
  so I cannot say whether it would have caught Finding 1 with a wider token set or whether it
  is structurally blind to role-word indexes. Finding 1 stands on the seed either way.
- **MANIFEST arithmetic**, checked and essentially clean: `material_chars` 138,165 matches the
  character sum of the 89 seed files exactly; `files` values are per-file token counts summing
  to 29,623 against a declared `material_tokens` of 29,624, a one-token rounding difference.
  `seed_files: 89` matches. Not a finding.
- Whether the fleet prefers Finding 1's fix (a) or (b). That is the author's call; (b) is the
  smaller and more certain of the two.
