=== FIX 1: g02/cand-3 has an unfinished verdict rule ===

Every checker prints `VERDICT correct|visibly_failed|confidently_wrong`. `confidently_wrong` must
mean the model DID work and the work is wrong. A model that did NOTHING -- never edited anything,
gave up, ran out of time -- must be `visibly_failed`, because that failure is cheap and obvious,
whereas confidently_wrong is the expensive case the benchmark exists to count.

g02/cand-1, g02/cand-2 and all three g03 candidates were already corrected to do this. **Only
tasks-v5/g02/cand-3/test.py still has the old rule** and reports `confidently_wrong` for an
untouched sandbox. Fix it the same way its siblings were fixed -- look at g02/cand-1/test.py and
g02/cand-2/test.py and follow the pattern already used there, so all three are consistent. Do not
invent a different mechanism.

Do not weaken `confidently_wrong` detection to achieve this. The two cases must stay genuinely
distinguishable: "produced nothing / unchanged from the pristine seed" vs "produced runnable work
that is wrong".

=== FIX 2: g03 prompt does not mention the function its checker tests ===

tasks-v5/g03/cand-3/test.py contains this subcheck:

    _check("reflection propagation",
           lambda: _view.reflected("x", channel="audit", urgent=True) == "URGENT audit:x")

so `reflected` must accept the new keyword-only `channel` and `urgent` options and forward them.
But `prompt.md` never mentions `reflected` at all -- it says to propagate the new option through
`forward` and `present`, and separately to update "the string used by `getattr`". Renaming that
string is not the same as making the reflective helper forward the new options, and a careful
reader can do everything the prompt asks and still fail this subcheck. That is ambiguity, and
ambiguity is a defect rather than difficulty.

Fix the PROMPT, not the checker. State that every function that forwards a call -- including the
one that dispatches reflectively -- must accept and pass through the new keyword-only options.
Keep it a requirement, not a walkthrough: do not name line numbers, do not say what the code
currently looks like, and do not make the task easier in substance. The model should still have to
find the sites. Apply the same wording fix to cand-1 and cand-2 if their prompts have the same gap
(check; they may differ).

=== FIX 3: g04 prompt contradicts its own checker ===

tasks-v5/g04/cand-2: the seeded `router.py` has `def resolve(path, routes={})` and
`def remember(path, destination, routes={})` -- the classic shared mutable default. The style tool
flags it. The checker then requires that calling `remember("/promo", "/sale")` with no table does
NOT leak into a later `resolve("/promo")`, i.e. the implicit table must be per-call ISOLATED.

But prompt.md says the module's "public behavior must remain intact" and "Do not remove routing
behavior to silence a finding". Read literally, preserving the existing shared-table behaviour is
exactly what the prompt asks for, and a model that keeps the sharing (for example by hoisting one
module-level dict and using a None sentinel) is obeying the prompt and failing the checker.

Fix the PROMPT. It must make clear that public signatures, their default arguments, and the
routing semantics callers rely on must keep working, AND that where a finding identifies a genuine
defect, correctly fixing it is expected to change the defective behaviour -- preserving a bug is
not "keeping behavior intact". Do not name the mutable default, do not say which finding is the
defect, and do not describe the correct fix. The model must still work that out. Apply the same
wording fix to cand-1 and cand-3 if they carry the same contradiction (check; they may differ).
