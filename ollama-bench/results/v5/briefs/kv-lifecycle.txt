WHAT TO BUILD

1. One cleanup barrier function, replacing kill_stray_servers(). Suggested signature:
       def cleanup_barrier(proc=None, *, reason="", idle_ceiling=4000, timeout=180) -> dict
   It must, in this order:
   a. If proc is given, terminate its whole PROCESS TREE, not just the parent. On Windows the reliable way is
          subprocess.run(["taskkill", "/PID", str(proc.pid), "/T", "/F"], capture_output=True, timeout=60)
      Call proc.terminate() first for a graceful attempt, wait briefly, then escalate to taskkill /T /F if it has not exited. Always reap with proc.wait() afterwards so no zombie handle is left.
   b. Kill any remaining llama-server.exe process regardless of whether we started it. Enumerate them with pid and executable path so the barrier can report WHICH processes it found, not merely that some existed. Use
          tasklist /FI "IMAGENAME eq llama-server.exe" /FO CSV /NH
      to get pids (parse the CSV with the csv module; the "no tasks" line is not CSV, handle it), then taskkill /PID <pid> /T /F each one. If you can get executable paths cheaply via a single CIM query, include them in the report; if the quoting is awkward, pids alone are acceptable — do not spend the run fighting PowerShell quoting.
   c. Wait until TCP port 18080 is actually FREE. Test it by binding, not by connecting: a connect-refused can also mean a socket in TIME_WAIT or a process mid-exit. Create a socket, do NOT set SO_REUSEADDR (on Windows SO_REUSEADDR lets you bind an in-use port and would make the test lie), attempt bind(("127.0.0.1", 18080)), close it. Success means free. This check is what catches a port holder whose image name is not llama-server — the fault that "matches on process name only" describes.
   d. Require THREE CONSECUTIVE quiescent VRAM samples, taken 2 s apart. A sample is quiescent iff vram_mib() succeeded (is not -1) and is <= idle_ceiling. A failed nvidia-smi read is NOT quiescent and resets the counter. Any non-quiescent sample resets the counter to zero.
   e. Re-check that no llama-server.exe process reappeared after the VRAM drain settled. If one has, the barrier has not succeeded.
   The whole barrier is bounded by `timeout` seconds. On expiry it returns failure.

   It must return a STRUCTURED result, never a bare bool, because the reason is the whole point:
       {"ok": True/False, "reason": "<short why, empty when ok>", "waited_s": <float>,
        "vram_samples": [<the samples taken>], "port_free": True/False,
        "killed_pids": [...], "stray_pids_remaining": [...]}
   Print one concise line to stdout when it starts and one when it finishes, including ok, waited_s and reason, so the sweep log shows the barrier working. Prefix them so they are greppable, e.g. "  [cleanup] ...".
