Luna takes 15/16, the best of any arm measured on this suite: a clean sweep of the tiny band
against GLM's 5/8, and level with GLM at 7/8 on the large band, with no timeouts, no
rate-limit events, and `codex exec` exiting 0 on all sixteen tasks. It is not the cheap arm —
it spends 4.2x GLM's summed wall on the tiny band, where GLM's failures are fast — but on the
large band it does the same work in 1397 s against GLM's 952 s while using a fifth of the
tokens, because GLM's g03 alone burned 614 s and 2.3M tokens flailing. The one large-band
failure, t04, is not a wrong analysis: the answer names the right file (`app/request_path.py`)
and a span the checker accepts, and the verdict `confidently_wrong` comes entirely from the
explanation sentence missing two of the checker's eight keyword groups — it wrote
"verification" where the checker wants `verify` or `credential` as a substring, and described
the block being created without using the word `failed` or `failure`. That is the checker
being stricter than its prompt, the same class of artifact
`local-llm-bench-desaturation-2026-09-05.md` records for round 2, and it is worth knowing that
the only fault in this arm's 16 tasks is a lexical one.

## Exact command

Per task, from inside the sandbox, prompt on stdin:

```
timeout 900 codex exec --skip-git-repo-check -C <sandbox> \
  -m gpt-5.6-luna -c model_reasoning_effort=high -c project_doc_max_bytes=0 \
  --color never -o <band>/trial-0/<task>.final.txt - < <suite>/<task>/prompt.md \
  > <band>/trial-0/<task>.codex.log 2>&1
```

## Notes on the arm

- `project_doc_max_bytes=0` keeps the sandbox's own context-file chain out of the run. The
  fleet's `~/.codex/AGENTS.md` still loads, as it does for every Codex run on this fleet;
  that is accepted and is the one respect in which this arm is not context-free. The floor it
  costs is visible in a control probe: a one-word prompt with no tools reported 4,839 tokens.
- **No rate-limit or usage-limit event occurred**, so the pool never dropped to four. The
  brief's warning about false positives was live: `large/t04`'s transcript contains four
  `429` hits, every one of them inside a source file the model read (`app/replies.py` returns
  `Response(429, ...)`). The driver's detector strips the echoed prompt and cuts the
  transcript at the first tool call before matching, and additionally never fires on a run
  that produced a final message, so those did not trigger a back-off.
- **Codex committed into the enclosing repository on two tiny-band tasks.** Under
  `danger-full-access` the g02 and g03 runs finished their work with `git commit`, and because
  each sandbox sits inside the scratch clone's worktree, the commits landed on that clone's
  `main` ("fix call spans", "migrate event api"). Both touch only their own sandbox paths, so
  no result is contaminated and grading reads the worktree anyway — but an arm run inside the
  campaign clone rather than a throwaway one would have written those commits into the real
  repository. Keep the sandboxes in a scratch clone, as this run did.
- Every task exited 0 within the 900 s cap; nothing was resumed or re-run.
