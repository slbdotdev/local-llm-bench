# 2026-01 configuration split

Release configuration moved from constants embedded in the batch importer to
three reviewed tables: source aliases, key aliases, and action policy. The
split was organizational, not a change in the API. The JSON snapshots and the
Python release-data view contain the same values and the same lookup order.

Global key aliases are `err` to `error`, `warn` to `warning`, `lat` to
`latency`, `dur` to `duration`, and `cfg` to `config`. Source-specific aliases
apply to the canonical source: platform maps `compile` and `compilation` to
`build`; service maps `request` and `req` to `requests`; frontend maps `paint`
and `draw` to `render`; worker maps `job` and `task` to `jobs`.

The release loader does not recursively apply aliases. An alias result is the
result for that stage. This keeps unknown and newly configured names stable and
makes the operation sequence testable. Case folding happens before the global
key lookup; source lookup happens after source canonicalization.
