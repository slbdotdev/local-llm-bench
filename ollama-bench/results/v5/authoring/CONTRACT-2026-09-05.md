# v5 authoring contract — amendment of 2026-09-05

Read `CONTRACT.md` first, in full. This page amends it. Where the two disagree, **this page
wins**. It exists because the plan of record changed on 2026-09-05
(`results/v5/plan-2026-09-05.md`, sections 2 and 3).

## A1. Synthetic context fill is withdrawn

`CONTRACT.md`'s section "Layout requirement for the context axis" described a prompt-side fill
mechanism that sized the prompt to a cell's token budget with extra material. **That mechanism is
withdrawn from every scored run.** It measured a model's tolerance for padding, which is not a
question this campaign asks.

What replaces it: **a task's context is the material the task genuinely requires.** The context
axis is now a property of the task, not a knob on the harness.

Everything else in that section still holds and still matters:

- the material needed to answer lives in files under `seed/`, never in `prompt.md`;
- `prompt.md` must not name the single file that holds the answer for a comprehension task;
- the checker must not care how many extra files exist;
- the answer must not be reachable by one trivially unique grep token.

## A2. Every candidate declares its material size, and is authored into a band

| band | seed material | the cell it runs in |
| --- | --- | --- |
| small | 4,000-8,000 tokens | 24k |
| medium | 12,000-20,000 tokens | 32k or 48k |
| large | 30,000-45,000 tokens | 64k |

**Material size is measured, not estimated by eye.** The measured constant for this suite is
**4.664 characters per token**. Material size is the total character count of every file under
`seed/` that a solver could reasonably have to read, divided by 4.664. Byte-for-byte:

```python
import os, json
chars = 0
for root, dirs, files in os.walk("seed"):
    dirs[:] = [d for d in dirs if d not in ("__pycache__", ".git")]
    for f in files:
        if f.endswith((".pyc", ".pyo")):
            continue
        chars += len(open(os.path.join(root, f), encoding="utf-8").read())
print(chars, round(chars / 4.664))
```

Write the result into `MANIFEST.json` beside `NOTES.md` in your candidate directory:

```json
{"task": "<id>", "candidate": "cand-5", "band": "large",
 "material_chars": 172345, "material_tokens": 36953,
 "chars_per_token": 4.664, "seed_files": 21}
```

**A candidate whose measured size falls outside its target band is not finished.** Add or remove
real material until it lands inside, and re-measure. Do not pad with filler to hit the number: if
the task does not need the material, the material does not belong in it. Grow the task instead —
more sources to reconcile, more modules in the tree, a longer history to search.

## A3. The working-margin rule

A cell's window must be at least **1.6x** the task's material, and the material must never exceed
about **60%** of the window. This is why the bands above stop where they do. At an earlier
acceptance run ~57.9k of a 65,536-token window was prompt and the agentic loop collapsed to a
single turn: that cell measured *less room to think*, not *more to read*. A task that needs more
than 45,000 tokens of material has no cell on this machine and must be cut down.

## A4. What "harder" means, in order of preference

The current suite is passed by every reference model on almost every trial, so it cannot separate
one model from another. That is the defect these variants exist to fix. Make a task harder in
this order; the first three are the good ones.

1. **More material that must be held at once.** The answer is decidable only after reading and
   reconciling several real sources. This is the axis of interest and it serves A2 at the same
   time.
2. **A trap that a plausible answer walks into.** Material that looks like it needs fixing and
   must be left alone; a claim that looks true and is not. A model that acts on everything it
   finds looks productive and is wrong.
3. **More steps that must all be right, in series.** Three steps that each feed the next are
   genuinely harder. Six independent sub-answers are graded like six easy tasks.
4. **A tighter output contract**, but only where the contract is stated exactly and checkably.
   Legitimate, but it measures instruction-following rather than comprehension, so it must not
   be the main lever.
5. **Longer wall or more output.** Weakest, and constrained by A5.

**Never, under any circumstance:** ambiguity, missing information, unstated conventions, trick
wording, or anything `prompt.md` does not say plainly. If two careful readers can disagree about
what the task asks, the task is broken, not hard. A task must be hard to DO and never hard to
UNDERSTAND.

## A5. More material does NOT mean more output

`CONTRACT.md`'s sizing limits are unchanged and are still non-negotiable:

- a competent reference solution stays **under 5,000 output tokens** (~200 lines of Python);
- the whole job is doable in **under 300 seconds** by a local model generating at ~45 tok/s;
- `prompt.md` stays well under 2,000 words.

Growing the reading and holding the writing constant is exactly the intent.

## A6. Comprehension tasks: at least half the variants have a negative correct answer

"Nothing found", "the claim is false", "leave it alone". A suite where the correct answer is
always positive rewards a model that always finds something. Say plainly in `NOTES.md` whether
your variant's correct answer is positive or negative.

## A7. Probe your own checker with a shaped near-miss set — this is now mandatory

`CONTRACT.md` asks for one wrong reference and one empty sandbox. That is no longer enough. One
checker in this suite scored a **completely correct** answer as `visibly_failed` because it
required the output file to end in exactly one newline. One reference model always emits that
newline and another does not, so the primary metric carried a model-dependent bias for a whole
gate round.

The reference solution is written by the same hand and the same habits as the checker, so it
cannot catch this. Before you report back, run your checker against **at least six deliberately
shaped near-misses** built from a *correct* answer, and record each outcome in `NOTES.md`:

1. correct content, no trailing newline;
2. correct content, two trailing newlines;
3. correct content, CRLF line endings;
4. correct content, one leading blank line;
5. correct content, trailing spaces on one line;
6. correct content, a different but equally valid ordering **if** the prompt does not fix the
   order — and if the prompt does fix the order, a violation of it, which must fail.

**Any of 1-5 that fails is a checker defect**, not a near-miss: the prompt does not specify those
things, so the checker must not depend on them. Fix the checker and re-run. Then, separately, one
genuinely wrong-but-plausible answer, which must produce `VERDICT confidently_wrong`, and an
untouched sandbox, which must produce `VERDICT visibly_failed` without a traceback.

## A8. What to deliver

Inside your candidate directory and nowhere else:

    prompt.md      the only thing the model under test sees
    test.py        the hidden checker
    seed/          the material, sized to the band
    ref/           your reference solution; never copied into the sandbox
    selfcheck.py   executes every example in prompt.md against ref/
    NOTES.md       authoring notes, per CONTRACT.md, plus the A7 table and the A6 answer
    MANIFEST.json  per A2
