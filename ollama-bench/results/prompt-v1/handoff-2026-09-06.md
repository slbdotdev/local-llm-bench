## Recommendation

**Deployment is supported on pass rate pending the `high` question, but measure `high` before deploying.**

The prompt to deploy is `pi-system-prompt.ts` + `pi-system-prompt.md` in this directory.

- **Supported.** `Hlineno` has 22/24 tiny passes and 7/7 large passes, with zero confidently-wrong
  large cells. It does not regress the large-band pass result against baseline.
- **Not supported.** The large-band cost is higher for `Hlineno`: 3,767,163 input tokens and
  1,679 seconds of wall time, versus baseline's 1,756,216 input tokens and 1,529 seconds.
  Two Hlineno cells and one baseline cell reached the 600-second limit, so this cost needs a
  `high` measurement before deployment.
- **Not yet tested.** `H` ranks with 22/24 tiny passes, 2 confidently-wrong cells, and 3,008 mean
  output tokens, but it has no large-band holdout. `Hlineno` also has 2 confidently-wrong tiny
  cells, with 3,897 mean output tokens, and is the only tested variant with matching large-band
  evidence.
- **Not tested at `high`.** Every row used `--think medium`; `pi-run` deploys at `high`.

By the required ranking, pass count over 24 comes first, then confidently-wrong count, then mean
output tokens. `H` and `Hlineno` tie at 22/24 and 2 confidently-wrong tiny cells, so H's lower
mean output is the tie-breaker, but H has no large-band result. Measure `Hlineno` at `high` before
deploying it into `ansible-slb`, with the large-band cost above as the reason for that check.

## The finding worth keeping

**Three of the five failures across both completed arms are the same defect: an off-by-one
line citation**, and the transcripts say exactly why.

| trial | wrote | correct | grader's name for it |
| --- | --- | --- | --- |
| `H` `t02#1` | `EVIDENCE: 26: if value < 1 or value > 65535:` | line 27 | `evidence` |
| `H` `t04#0` | `LINES: 6-8` | `7-9` | `cited line span` |
| `baseline` `t04#0` | (same span error) | `7-9` | `cited line span` |

In each the rest of the answer is right — the correct file, the correct source line, a correct
explanation — and only the number is wrong. Splitting the traces by tool use separates passes
from failures cleanly:

| trial | how it got the line number | result |
| --- | --- | --- |
| `t04#0` fail | none: `ls`/`find`, then `read gateway.py` | off by one |
| `t04` pass | a per-file numbering loop, then `cat answer.txt` to check | correct |
| `t02#1` fail | one `grep -rn`, then `read` | off by one |
| `t02` pass | `grep -rn` **and** a second confirming `grep -n` | correct |

**pi's `read` tool does not number its output.** Numbering commands produced correct citations;
counting by eye off `read` was off by one, a harness property addressed by `lineno`/`Hlineno`.

## The most surprising observations

1. **The default prompt says nothing about finishing a task:** pi's prompt is **2,685 characters**;
   ten guidelines concern `edit`, with no output-path, full-specification, or verification rule.
2. **A rate limit can look like a bad answer:** `g04` scored 9/12 from an unmodified seed after
   `429 rate_limit_error 1302`; only `stop_reason=error` exposed it.
3. **The quota endpoint lags:** 93.5% at 06:41 became **100.0%** at 06:51, ten minutes later.
4. **The resume path failed at reset:** the Z.ai quota API returned a null `nextResetTime` for
   the untouched five-hour window after the 08:50 UTC reset. That crashed `zai-quota.py`, which
   now prints `n/a`, and the fleet's `plan-usage.py`, patched in `ansible-slb`. The control session
   launched the endgame at 03:38 MDT, 48 minutes late.
5. **The credit model was too high:** it predicted about 1,200 credits for one seven-task large
   arm, while the measured baseline holdout left the window at 7.3% used, about 146 credits,
   after Hlineno tiny's 17 cells had also run.

## The deliverable, and the proof it is what was measured

`pi-system-prompt.ts` and `pi-system-prompt.md`, loaded beside `pi-resilience.ts`:

```
pi -e ~/.claude/skills/pi-run/scripts/pi-resilience.ts -e <dir>/pi-system-prompt.ts
```

It **inserts** the six guideline bullets immediately after pi's last standing guideline; it does
not replace the system prompt. If that anchor is absent, the extension appends the block and says so on stderr.

**Byte-identity proof.** Simulating the extension's insertion against the captured default
prompt reproduces `variants/Hlineno.md` exactly — 4,107 characters on both sides, `==` true.
The captured default itself was proved sound the same way: an arm run with `-e baseline.ts -e
capture2.ts` produced a chained prompt byte-identical to pi's own default once the per-sandbox
cwd line is normalised (tag `identity`, D6).

## Baseline and best prompts, side by side

`variants/baseline.md` is pi's default verbatim (per-trial cwd replaced by `<<<CWD>>>`);
`variants/Hlineno.md` is the candidate. The whole diff is six added bullets:

```diff
  - Be concise in your responses
  - Show file paths clearly when working with files
+ - When an answer must cite a line number or a line range, take that number from a command
+   that prints line numbers (`grep -n`, `cat -n`, `nl`) and then confirm it by looking at that
+   exact numbered line again. The read tool does not number its output, and counting lines by
+   eye off a file listing is reliably off by one.
+ - When the task names a specific output file for the result, write the complete result to
+   exactly that file path and name — do not substitute a different name or location
+ - Leave explicitly provided input or source files unchanged unless the task explicitly says
+   to modify them in place; apply changes only to the files the task names as outputs
+ - When a task requires a minimal fix (e.g. 'exactly one line'), change that single line as
+   written — substitute the buggy line's content in place; do not reorder, swap, or
+   restructure lines, and do not rewrite surrounding code
+ - Before finishing, verify your change: run the project's own build/test commands (not ad-hoc
+   harnesses that fight the project's package layout), and diff old vs new to confirm the
+   change is exactly as minimal as instructed
+ - When verifying, never move or copy the named source/output file and never create a
+   duplicate package directory (e.g. java_programs/) next to the original — that leaves two
+   copies for the grader. Verify in place, or copy to a separate temp directory (e.g. under
+   /tmp) and build/test there, leaving the task's files exactly where they were

  Pi documentation (read only when the user asks about pi itself, ...)
```

Bullets two to six are the five published QuixBugs guidelines, verbatim from commit `f089a6e`
behind `heyneo.com/blog/pi-agent-quixbugs-optimization`; the first bullet is this campaign's own.

## The credit model

Fitted to a marginal reading of 226 credits over 12 cells of known token counts, and consistent
with the plan overview's 2.3x input / 8x output metering:

```
credits ~= 0.164 * (input_k * 2.3 + output_k * 8)
```

The model predicted about 1,200 credits for one seven-task large arm. The measured baseline
holdout consumed about 146 credits and left the five-hour reading at 7.3% used, after
Hlineno tiny's 17 cells had also run. The large-band estimate was therefore high by roughly
eight times in this campaign.

| | credits |
| --- | ---: |
| one tiny arm (8 tasks x 3 trials) | ~370-450 |
| one **large** arm (8 tasks x 1 trial) | **~1,200** |
| measured seven-task baseline holdout | **~146** |
| both large arms, 7 tasks (no `g02`) | fit in the reset window |

The two large arms and the Hlineno tiny tail fit in the reset window. `g02` alone is **1.40M of
3.03M** input tokens (**46%**) and is least discriminating, so dropping it bought seven tasks on
both arms; the holdout is therefore seven tasks and **partial**.

Read a finished arm from its JSON (`results/prompt-v1/<tag>.json`), never from a console tail.

**Check for contamination before believing any row:**

```bash
python3 -c "
import json,sys
d=json.load(open('results/prompt-v1/'+sys.argv[1]+'.json'))['glm-5.3-flash']['runs']
print('cells',len(d),'| cells with an error turn',
      sum(1 for r in d if r.get('stop_reasons',{}).get('error')),
      '| rc!=0',sum(1 for r in d if r.get('rc',0)!=0))" Hlineno-tiny
```

A cell with `stop_reason=error`, `tool_calls=0` and `out_tokens=0` is a rate-limited run that
was graded anyway; it is not a result. `supervise.sh` already drops and refills cells whose pi
was killed from outside (`rc != 0` and not `timed_out`).

### 3. Stop everything cleanly

```bash
bash /home/slb/bench-prompt/ollama-bench/results/prompt-v1/stop.sh   # arms only
for p in $(ps -eo pid,cmd | grep -E 'quotaguard\.sh|resume_after_reset\.sh' \
           | grep -v grep | awk '{print $1}'); do kill "$p"; done
```

`stop.sh` identifies this campaign's processes by `prompt-v1` in their command lines and walks
the parent map to reach their `node.exe` children. **Never kill by image name**: the v6
campaign's `kill_pi.ps1` did exactly that and force-killed this campaign's trials all evening
(its own `results/v6/decisions.md` D6-37 records it, and it is now rescoped by ancestry).

### 4. Relaunch a single arm

```bash
cd /home/slb/bench-prompt/ollama-bench
bash results/prompt-v1/launch.sh Hlineno-tiny Hlineno tiny 3         # resumes; never restarts
PV1_TASKS="g01,g03,g04,t01,t02,t03,t04" \
  bash results/prompt-v1/launch.sh Hlineno-large Hlineno large 1     # the second holdout arm
PV1_TASKS="g01,g03,g04,t01,t02,t03,t04" \
  bash results/prompt-v1/launch.sh base-large baseline large 1
```

`launch.sh <tag> <variant> <tiny|large> <trials>` always loads `pi-resilience.ts` first, then
the variant, then `trace.ts`, and detaches under `setsid --fork`. Three rules, each of which
cost this campaign a restart:

- **Two concurrent arms, never three.** Three exceed the plan's request rate and manufacture
  `429 rate_limit_error 1302` failures (D13).
- **Never launch above 80% of the 5-hour window.** Read it first:
  `source ~/.config/devbox/env && python3 results/prompt-v1/zai-quota.py precheck`.
  Never take the weekly window past 60%.
- **Re-arm the guard if it has tripped** (it exits after firing):
  `rm -f logs/quota.tripped && setsid --fork bash results/prompt-v1/quotaguard.sh < /dev/null > /dev/null 2>&1`

`publish.sh` stages only `ollama-bench/results/prompt-v1/`, commits in the scratch clone,
