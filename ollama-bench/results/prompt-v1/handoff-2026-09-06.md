## Recommendation

**Deploy with a caveat — but not tonight, and not on this evidence alone.**

The prompt to deploy is `pi-system-prompt.ts` + `pi-system-prompt.md` in this directory. What
supports it and what does not:

- **Supported.** `H` (five published guidelines) beat pi's default prompt on every secondary
  axis at once, over 24 trials each with no error turns and no timeouts on H: 18% fewer output
  tokens, 17% fewer input tokens, 23% less wall clock, one fewer confidently-wrong answer, and
  **two timeouts on the baseline against none on H**. It turned `g03`, the coordinated
  three-module migration, from 1/3 into 3/3.
- **Not supported.** The pass count barely moved: 21/24 to 22/24 is one trial, which is noise.
  Anyone reading only the headline number should read the cost table instead.
- **Not yet tested at all.** The **large band holdout has not run**. The brief is explicit that
  a variant regressing the large band is not recommended whatever the tiny band said, so the
  present recommendation is provisional by construction. `Hlineno`'s own tiny row is 7/24 cells.
- **Not tested at `high`.** Every row here is `--think medium`, chosen to stay comparable with
  the existing GLM reference rows (D3). `pi-run` deploys at `high`.

So: do not deploy it into `ansible-slb` until the holdout in [How to re-attach](#how-to-re-attach)
has run and `Hlineno` has not regressed. If it holds, deploying is well supported; the
downside risk measured so far is zero and the cost saving is real.

## The finding worth keeping

**Three of the five failures across both completed arms are the same defect: an off-by-one
line citation**, and the transcripts say exactly why.

| trial | wrote | correct | grader's name for it |
| --- | --- | --- | --- |
| `H` `t02#1` | `EVIDENCE: 26: if value < 1 or value > 65535:` | line 27 | `evidence` |
| `H` `t04#0` | `LINES: 6-8` | `7-9` | `cited line span` |
| `baseline` `t04#0` | (same span error) | `7-9` | `cited line span` |

In each the rest of the answer is right — the correct file, the correct source line, a correct
explanation — and only the number is wrong. Splitting the traces by tool use separates passes
from failures cleanly:

| trial | how it got the line number | result |
| --- | --- | --- |
| `t04#0` fail | none: `ls`/`find`, then `read gateway.py` | off by one |
| `t04` pass | a per-file numbering loop, then `cat answer.txt` to check | correct |
| `t02#1` fail | one `grep -rn`, then `read` | off by one |
| `t02` pass | `grep -rn` **and** a second confirming `grep -n` | correct |

**pi's `read` tool does not number its output.** Every trial that took its number from a
numbering command was right; every trial that counted by eye off `read` was one out. That is a
harness property, not a model weakness, and one sentence of prompt addresses it — which is
what `lineno` is, and what `Hlineno` adds to `H`.

## The three most surprising observations

1. **The default prompt says nothing about finishing a task.** pi's system prompt is 2,685
   characters, and ten of its guidelines are about how to call `edit`. There is no rule about
   writing to the named output path, none about reading a specification to the end, none about
   verifying before finishing. The whole measured gain comes from adding what was simply absent.
2. **A rate limit is indistinguishable from a bad answer once it has been graded.** Under three
   concurrent arms the plan returned `429 rate_limit_error 1302`; a trial then ran zero tools,
   emitted zero tokens, and was graded anyway. `g04` scored 9/12 that way — the *unmodified
   seed* being marked, and banked as a variant's failure. It was `stop_reason=error` in the JSON
   that gave it away, not the score. **A benchmark that grades whatever is in the sandbox will
   quietly score the seed.**
3. **The quota endpoint lags.** Every arm was stopped at 06:41 UTC with the window at 93.5%; it
   kept climbing to 100.0% by 06:51, ten minutes and ~130 credits later, with nothing of this
   campaign running. A guard threshold has to leave room for the lag, and a reading is a floor,
   not a current value.

## The deliverable, and the proof it is what was measured

`pi-system-prompt.ts` and `pi-system-prompt.md`, loaded beside `pi-resilience.ts`:

```
pi -e ~/.claude/skills/pi-run/scripts/pi-resilience.ts -e <dir>/pi-system-prompt.ts
```

It **inserts** the six guideline bullets from the sibling `.md` immediately after pi's own last
standing guideline (`- Show file paths clearly when working with files`), which is exactly
where the measured variant put them. It does **not** replace the system prompt. That matters:
the captured baseline contains this Windows box's `scoop` documentation paths and today's
four-tool list, and a full replacement would freeze both and ship them to every Linux host.
If pi's default guidelines ever change and the anchor is absent, the extension appends the
block at the end and says so on stderr.

**Byte-identity proof.** Simulating the extension's insertion against the captured default
prompt reproduces `variants/Hlineno.md` exactly — 4,107 characters on both sides, `==` true.
The captured default itself was proved sound the same way: an arm run with `-e baseline.ts -e
capture2.ts` produced a chained prompt byte-identical to pi's own default once the per-sandbox
cwd line is normalised (tag `identity`, D6).

## Baseline and best prompts, side by side

`variants/baseline.md` is pi's default verbatim (with the per-trial cwd replaced by a
`<<<CWD>>>` token). `variants/Hlineno.md` is the candidate. The whole diff is six added
bullets and nothing else:

```diff
  - Be concise in your responses
  - Show file paths clearly when working with files
+ - When an answer must cite a line number or a line range, take that number from a command
+   that prints line numbers (`grep -n`, `cat -n`, `nl`) and then confirm it by looking at that
+   exact numbered line again. The read tool does not number its output, and counting lines by
+   eye off a file listing is reliably off by one.
+ - When the task names a specific output file for the result, write the complete result to
+   exactly that file path and name — do not substitute a different name or location
+ - Leave explicitly provided input or source files unchanged unless the task explicitly says
+   to modify them in place; apply changes only to the files the task names as outputs
+ - When a task requires a minimal fix (e.g. 'exactly one line'), change that single line as
+   written — substitute the buggy line's content in place; do not reorder, swap, or
+   restructure lines, and do not rewrite surrounding code
+ - Before finishing, verify your change: run the project's own build/test commands (not ad-hoc
+   harnesses that fight the project's package layout), and diff old vs new to confirm the
+   change is exactly as minimal as instructed
+ - When verifying, never move or copy the named source/output file and never create a
+   duplicate package directory (e.g. java_programs/) next to the original — that leaves two
+   copies for the grader. Verify in place, or copy to a separate temp directory (e.g. under
+   /tmp) and build/test there, leaving the task's files exactly where they were

  Pi documentation (read only when the user asks about pi itself, ...)
```

Bullets two through six are the five published QuixBugs guidelines, taken verbatim from
`pi/packages/coding-agent/src/core/system-prompt.ts` at commit `f089a6e` of
`github.com/dakshjain-1616/Pi-agent-optimisation-`, the H3 revision behind
`heyneo.com/blog/pi-agent-quixbugs-optimization` (dev 82%→95%, sealed holdout 80%→95%). The
first bullet is this campaign's own, from the transcripts.

## The credit model

Fitted to a marginal reading of 226 credits over 12 cells of known token counts, and consistent
with the plan overview's 2.3x input / 8x output metering:

```
credits ~= 0.164 * (input_k * 2.3 + output_k * 8)
```

It reproduces the campaign's whole 2,001 credits to within about 20%, so use it with margin.
What it implies, and what shaped the endgame:

| | credits |
| --- | ---: |
| one tiny arm (8 tasks x 3 trials) | ~370-450 |
| one **large** arm (8 tasks x 1 trial) | **~1,200** |
| both large arms, all 8 tasks | ~2,400 — **more than one whole window** |
| both large arms, 7 tasks (no `g02`) | ~1,300 |

`g02` alone is 1.40M of the large band's 3.03M input tokens — 46% of the band on one task — and
it is the least discriminating task in it, passed by every GLM arm on record. Dropping it buys
seven tasks on **both** arms instead of eight on one. That is why the holdout is scoped
`g01,g03,g04,t01,t02,t03,t04`, and the resulting holdout is **partial**; say so wherever it is
quoted.

## How to re-attach

Everything below runs from WSL on FRACTAL. The scratch clone is `/home/slb/bench-prompt`; the
variants live at `C:\Users\slb\bench-prompt-variants\` because the Windows interpreter cannot
see `/home/slb`. **Never poll a process name** — poll the outcome file.

### 1. Did the resume fire, and what did it launch?

```bash
cd /home/slb/bench-prompt/ollama-bench/results/prompt-v1
cat logs/endgame.started 2>/dev/null || echo "resume has NOT fired yet"
tail -20 logs/quota.log                       # the reset, then the launches
ps -eo pid,etime,cmd | grep -E 'resume_after_reset|quotaguard|supervise\.sh' | grep -v grep
```

`resume_after_reset.sh` polls the quota every 120 s, and at the reset (5-hour window under 25%)
it restarts `quotaguard.sh` and launches **`Hlineno-tiny`** (resuming at cell 8 of 24) and
**`base-large`** (holdout, 7 tasks, 1 trial) together. It writes `logs/endgame.started` when it
has done so. It was armed at 06:52 UTC and the reset is 08:50 UTC.

### 2. Read each arm's progress

```bash
cd /home/slb/bench-prompt/ollama-bench
bash results/prompt-v1/poll.sh Hlineno-tiny base-large Hlineno-large
PV1_FAILS=1 python3 results/prompt-v1/summarize.py base-tiny H-tiny Hlineno-tiny
```

Read a finished arm from its JSON (`results/prompt-v1/<tag>.json`), never from a console tail.
An arm is complete when `logs/<tag>.outcome` exists and says `rc=0` with `cells=N/N`.

**Check for contamination before believing any row:**

```bash
python3 -c "
import json,sys
d=json.load(open('results/prompt-v1/'+sys.argv[1]+'.json'))['glm-5.3-flash']['runs']
print('cells',len(d),'| cells with an error turn',
      sum(1 for r in d if r.get('stop_reasons',{}).get('error')),
      '| rc!=0',sum(1 for r in d if r.get('rc',0)!=0))" Hlineno-tiny
```

A cell with `stop_reason=error`, `tool_calls=0` and `out_tokens=0` is a rate-limited run that
was graded anyway; it is not a result. `supervise.sh` already drops and refills cells whose pi
was killed from outside (`rc != 0` and not `timed_out`).

### 3. Stop everything cleanly

```bash
bash /home/slb/bench-prompt/ollama-bench/results/prompt-v1/stop.sh   # arms only
for p in $(ps -eo pid,cmd | grep -E 'quotaguard\.sh|resume_after_reset\.sh' \
           | grep -v grep | awk '{print $1}'); do kill "$p"; done
```

`stop.sh` identifies this campaign's processes by `prompt-v1` in their command lines and walks
the parent map to reach their `node.exe` children. **Never kill by image name**: the v6
campaign's `kill_pi.ps1` did exactly that and force-killed this campaign's trials all evening
(its own `results/v6/decisions.md` D6-37 records it, and it is now rescoped by ancestry).

### 4. Relaunch a single arm

```bash
cd /home/slb/bench-prompt/ollama-bench
bash results/prompt-v1/launch.sh Hlineno-tiny Hlineno tiny 3         # resumes; never restarts
PV1_TASKS="g01,g03,g04,t01,t02,t03,t04" \
  bash results/prompt-v1/launch.sh Hlineno-large Hlineno large 1     # the second holdout arm
PV1_TASKS="g01,g03,g04,t01,t02,t03,t04" \
  bash results/prompt-v1/launch.sh base-large baseline large 1
```

`launch.sh <tag> <variant> <tiny|large> <trials>` always loads `pi-resilience.ts` first, then
the variant, then `trace.ts`, and detaches under `setsid --fork`. Three rules, each of which
cost this campaign a restart:

- **Two concurrent arms, never three.** Three exceed the plan's request rate and manufacture
  `429 rate_limit_error 1302` failures (D13).
- **Never launch above 80% of the 5-hour window.** Read it first:
  `source ~/.config/devbox/env && python3 results/prompt-v1/zai-quota.py precheck`.
  Never take the weekly window past 60%.
- **Re-arm the guard if it has tripped** (it exits after firing):
  `rm -f logs/quota.tripped && setsid --fork bash results/prompt-v1/quotaguard.sh < /dev/null > /dev/null 2>&1`

### 5. Render the final handoff once the holdout lands

```bash
cd /home/slb/bench-prompt/ollama-bench
python3 results/prompt-v1/render_handoff.py > /tmp/pv1tables.md
```

`render_handoff.py` already knows the holdout tags `base-large` and `Hlineno-large` and fills
their column in as soon as those JSONs exist. Replace everything from `## Ledger` to the
`## The deliverable` heading in this file with its output, then rewrite **Recommendation**
against the rule the brief sets: *a variant that regresses the large band is not recommended
whatever the tiny band said*. Rank by pass count over 24, then by confidently-wrong count,
then by mean output tokens.

Then publish:

```bash
bash /home/slb/bench-prompt/ollama-bench/results/prompt-v1/publish.sh "prompt campaign handoff"
```

`publish.sh` stages only `ollama-bench/results/prompt-v1/`, commits in the scratch clone,
mirrors the directory into `/mnt/d/local-llm-bench`, commits and pushes there, retrying an
index lock five times at 30 s. It **fetches and pulls only when behind, and never
`--autostash`**: the v6 campaign keeps live uncommitted result files in that tree and an
autostash would move them out from under a running job.

### What a fresh session should decide first

1. Whether to spend the fresh window on the **holdout** (essential; the recommendation above is
   provisional without it) or on finishing `Hlineno-tiny`. If both will not fit, the holdout
   wins — `Hlineno`'s tiny row can be quoted as partial, but a recommendation with no large-band
   evidence cannot be made at all.
2. Whether to re-measure at `--think high`, which is what `pi-run` actually deploys, before any
   deployment into `ansible-slb`.
3. Whether `lineno` alone is worth a run. It would attribute the gain: if `lineno` alone matches
   `Hlineno`, the fleet needs one sentence rather than six.
